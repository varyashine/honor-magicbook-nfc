# honor-magicbook-nfc

Всё, что я выяснил про NFC-метку, встроенную в ноутбуки HONOR MagicBook,
плюс небольшая утилита для работы с ней на Linux. Чип: Shanghai Fudan
**FM11NT082C**, в ACPI виден как `NTAG0001`, на шине I²C сидит по адресу
`0x57`.

У утилиты нет зависимостей: только стандартная библиотека Python 3,
fcntl и ctypes.

## Где физически находится NFC-модуль

Строго в центре тачпада. Не у края и не в углах корпуса. Положите
телефон в центр тачпада, и он увидит метку.

## Что лежит в метке с завода

```
0000: 1d 19 db 57 3c 07 00 10  2b b0 ff ff e1 10 6d 00   локи ff ff @0x0A, CC @0x0C
0010: 03 8c 91 01 33 55 04 77  77 77 2e 68 69 68 6f 6e   NDEF TLV, URI-запись
0020: 6f 72 2e 63 6f 6d 2f 67  6c 6f 62 61 6c 2f 73 75   ...
0048: MIME-запись application/vnd.huawei.handoff.ndfmsg + 44 байта токена
```

Две NDEF-записи: URI на
`https://www.hihonor.com/global/support/magic_link_welcome/` и MIME-запись
`application/vnd.huawei.handoff.ndfmsg`, которую фирменный софт Honor
обновляет для функции One-Tap (передача касанием). Телефоны показывают
«UID» `1D:19:DB:3C:07:00:10`, но это просто первые байты блока 0 EEPROM:
чип отдаёт начало памяти как идентификатор.

## Что получилось

- Надёжное чтение всей пользовательской области по I²C на Linux без
  вендорского софта. Работают оба варианта транзакции: запись
  2-байтового big-endian указателя и затем чтение, или combined
  (repeated START).
- Бэкап 872 байт (`0x0010`-`0x0377`).
- Разбор NDEF (URI с префикс-кодами, текстовые и MIME-записи).
- Запись в страницы, оставленные незаблокированными, то есть в область
  токена handoff (`0x0070`-`0x008D`). Это ровно то, что нужно обновлять
  софту Honor, отсюда и странная карта, где пишется только часть памяти.
- Определение точного варианта чипа по лок-байтам, см. ниже.

## Что не получилось на моей машине

Ноутбук, на котором всё это делалось: MagicBook 14 Pro 2023, версия
**«Only for China Mainland»**: RTX 3050, i5, 16 ГБ + 1 ТБ, SKU `GLO-G561`
(DMI product name `GLO-GXXX`). На нём:

- **Любая I²C-запись в NDEF-область получает NAK.** Байт-в-байт заводские
  данные, формат блока как у вендорского драйвера, 150+ попыток, пока
  телефон читает метку по радиоканалу. Результата нет, errno 121.
- Запись в конфигурационные регистры (`0x0388` dyVal, `0x038C` fdMode)
  тоже получает NAK.
- **Запись с телефона тоже не работает.** NFC Tools на Android читает
  метку (Type A и ISO-DEP, то есть Type 4) и показывает «WRITABLE: YES»,
  но это неправда: каждая попытка записи заканчивается write error.
- iPhone метку не видит вообще.
- Windows-драйвер тоже не помогает: я разобрал `SpbNfcDriver.sys`, его
  диспетчер записи (`0x140003160` в Ghidra) сверяет SHA-256 данных с
  вшитыми дайджестами. Все четыре дайджеста подобраны: это SHA-256
  кусков заводского URL (`www.hihon`, `or.com/global/su`,
  `pport/magic_link`, `_welcome/`). То есть драйвер пропускает только
  заводской URL и не может записать другой адрес, даже если чип его
  принял бы.
- Поиск не того даташита отнимает день: FM11NT021 это бесконтактная Type 2
  метка на 144 байта без I²C. Это не наш чип, хотя форумы и строки в ACPI
  наводят на него.
- После серии попыток записи чип на время зависает и отвечает NAK даже на
  чтение. Через 10-30 секунд он приходит в себя. Поэтому утилита ждёт и
  повторяет чтение.
- Побочный эффект: одна из моих пробных записей вписала байт `0x58` внутрь
  заводского URL, и телефоны теперь читают
  `https://www.hihonor.com/global/suXport/magic_link_welcome/`. Всё
  остальное я восстановил из бэкапа, а эта страница после серии записей
  перестала их принимать. Возможно, после перезагрузки её удастся
  восстановить через `python3 nfc_tool.py restore`. Для меня это не
  страшно: заменить этот URL и было целью.

## Вердикт, и почему ваша машина может отличаться

Ответ есть в таблице заказа из даташита FM11NT082C:

| Суффикс | Статические лок-биты с завода | I²C-запись в пользовательскую область |
|---|---|---|
| **NTCZ** | `0000h` | работает |
| **NTCI** | `FFFFh` | NAK навсегда |

Лок-биты одноразовые (OTP): установить можно, сбросить нельзя, в этом их
смысл. Судя по всему, в ноутбуки Honor попадают оба варианта; какой
достанется вам, вероятно, зависит от модели или партии.

Мои лок-байты по адресу `0x000A` читаются как `ff ff`. Это NTCI: биты
установлены на заводе, программно их не сбросить.

[ZhuRuoLing/magicbookartd](https://github.com/ZhuRuoLing/magicbookartd)
реализует `nfc write-url` для MagicBook Art 14, и, по словам автора, там
запись работает. В его документации чип указан как FM11NT082C-NTCZ.
Утилита в этом репозитории использует ту же аккуратную процедуру записи,
так что если `check` покажет NTCZ, есть реальный шанс, что у вас
получится.

## Быстрый старт

```sh
sudo modprobe i2c-dev
python3 nfc_tool.py check                  # вариант чипа + текущая NDEF
python3 nfc_tool.py read --out backup.bin  # дамп 872 байт
```

Запись, только для NTCZ:

```sh
python3 nfc_tool.py write-url https://example.com --backup before.bin
python3 nfc_tool.py write-text "привет" --lang ru
python3 nfc_tool.py restore before.bin     # откат
```

Процедура записи осторожная: проверка CC, бэкап, обнуление длины TLV,
перезапись изменённых 16-байтных блоков, запись первого блока в самом
конце (это и публикует новую NDEF), полная проверка. Пока выполняется
любая команда, держите телефоны подальше от тачпада.

Если у вас NTCI, как у меня, а свой URL при касании ноутбука всё-таки
нужен, реалистичный вариант: недорогой стикер NTAG213 в центре тачпада.
Его можно записать с любого Android через NFC Tools или с этого же
ноутбука через дешёвый USB-ридер. Со встроенной меткой он нормально
уживается: телефон читает ту, что ближе к его антенне.

## Заметки о протоколе

Полная карта памяти, форматы транзакций и разбор Windows-драйвера лежат в
[docs/PROTOCOL.md](docs/PROTOCOL.md) и
[docs/RESEARCH.md](docs/RESEARCH.md). Кратко:

- Пользовательская область `0x0010`-`0x0377`, 872 байта, NDEF TLV `03 8c`
  с адреса `0x0010`.
- CC по адресу `0x000C` должен читаться как `E1 10 6D 00`; заодно это
  проверка, что вы обращаетесь к нужному чипу на общей шине. На той же
  шине висит HID-устройство с адресом `0x2B`, его не трогайте.
- Статические лок-байты по адресу `0x000A`, регистры с `0x0388`, байт
  fdMode по адресу `0x038C`, заводское значение `06`.
- Запись: одна транзакция `[addr_hi, addr_lo]` плюс до 16 байт с
  выравниванием на 16 байт. По даташиту программирование занимает 10 мс,
  утилита ждёт 20 мс и перечитывает. Неудавшуюся запись вслепую не
  повторяйте.
